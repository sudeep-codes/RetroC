# BENCHMARKS

Never write numbers here that were not measured. Fill the result tables from `bench/results/*.json`.

## 1. Setup
- Same machine for all runs; record CPU model, RAM, OS, compiler, flags (`-O2`).
- Warm-up 3 runs, then median of 11 runs; report min and max too.
- Fixed seeds for data generators. Inputs generated by `bench/gen_workload`.
- Timing excludes parsing/compiling and data loading unless stated; report history-recording overhead separately.

## 2. Workloads
| ID | Description | Size | Pipeline |
|---|---|---|---|
| W1 | Sensor log | 100k records | filter valid -> map normalize -> map scale -> filter range -> reduce sum -> scalar avg |
| W2 | Orders/users join | 50k users, 200k orders | join -> map amount -> filter -> reduce |
| W3 | Deep pipeline | 100k records | 12 chained map/filter stages + reduce |
| W4 | Reduce-heavy | 1M ints | map -> reduce (stress for O(n) reduce; tree_reduce in stretch) |
Also run W1 at 10k and 1M to show scaling.

## 3. Edit scenarios
| ID | Edit |
|---|---|
| E-A | modify 1 input record |
| E-B | modify 1% of input records |
| E-C | insert a map near the pipeline start |
| E-D | insert a map near the pipeline end |
| E-E | delete a middle stage |
| E-F | insert an identity map (expect ~100% reuse downstream) |

## 4. Systems compared
| ID | System | Notes |
|---|---|---|
| B0 | Full rerun of the edited program | the baseline that matters |
| B1 | Stage-level invalidation (coarse): any change to a node's input recomputes the whole node | implement as a flag in our runtime so only granularity differs |
| B2 | RetroC (record-level memo + early cutoff) | the system |
| B3 | Differential Dataflow or Adapton, modify-input only | stretch; label clearly as different system and language |

## 5. Metrics
- Wall time (ms), median of 11.
- Operations evaluated (lambda evals + reduce steps) and reuse %.
- Speedup = B0 time / B2 time. Also B1 / B2 to isolate the value of fine-grained reuse.
- History overhead: first run with recording / first run plain.
- Memory: memo bytes / input bytes.
- Correctness: every benchmark run also passes `verify`.

## 7. Honesty rules for the report
- Show cases where RetroC is slower or near 1x (e.g. insert at the pipeline start that changes most records; O(n) reduce).
- State that results are for the mini-language on this machine, not a general claim.
- Do not call numbers "typical" unless several workloads and sizes support it.
